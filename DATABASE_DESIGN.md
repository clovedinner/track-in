# Database Design, Initial Release

This document is the implementation plan for the first PostgreSQL migration. It follows the product contract in `AGENTS.md`; it does not add routing, offer, attribution, or reporting features outside that scope.

## Chosen data-layer direction

- Use Neon PostgreSQL, with `timestamptz` for every timestamp and `uuid` primary keys generated by PostgreSQL through `gen_random_uuid()` from the `pgcrypto` extension.
- Use Prisma ORM with checked-in Prisma Migrate SQL migrations. Runtime queries use Neon's pooled connection; Prisma migration and Studio commands use Neon's direct connection.
- Migrations are append-only. Development resets may recreate a local database, but production changes must be forward migrations with a reviewed rollback or recovery procedure.
- Application timestamps are written as UTC instants. Date grouping for the dashboard stays a query concern until the reporting timezone is chosen.
- Monetary amounts use signed `bigint` minor units plus an uppercase three-character ISO 4217 `char(3)` currency. The MVP should reject negative conversion values unless refunds are deliberately added later.

## Initial migration layout

1. Enable `pgcrypto`.
2. Create enum types for campaign and postback states.
3. Create `traffic_sources` and `campaigns`.
4. Create immutable `clicks`.
5. Create `conversions` and the durable `outbound_postbacks` outbox.
6. Create constraints and query indexes in the same migration.

Initial migration name: `20261004000000_initial_tracking_schema`.

## Tables

### `traffic_sources`

One configured ad-platform account or destination for outbound conversion reporting.

| Column | Type | Rules |
| --- | --- | --- |
| `id` | `uuid` | Primary key, generated in PostgreSQL. |
| `name` | `text` | Required, unique case-insensitively through a unique index on `lower(name)`. |
| `type` | `text` | Required provider discriminator such as `meta_conversions_api`; validation belongs in the adapter/configuration layer. |
| `enabled` | `boolean` | Required, defaults to `true`. |
| `credential_secret_ref` | `text` | Nullable reference to an environment/secret-store key. It is never credential material. |
| `configuration` | `jsonb` | Required, defaults to `{}`; non-secret provider settings and token mapping only. |
| `retry_policy` | `jsonb` | Required, defaults to `{}`; bounded retry settings only. |
| `created_at`, `updated_at` | `timestamptz` | Required, default `now()`. Update `updated_at` in application writes, not a hidden trigger. |

No generic integration catalog is implied by this table. Phase 2 introduces each adapter deliberately.

### `campaigns`

A tracking configuration, not a mirrored ad-platform campaign.

| Column | Type | Rules |
| --- | --- | --- |
| `id` | `uuid` | Primary key. |
| `slug` | `text` | Required, unique case-insensitively. Restrict to lowercase public-safe slugs in application validation. |
| `name` | `text` | Required. |
| `status` | `campaign_status` | Required enum: `active`, `paused`, `archived`; defaults to `paused`. |
| `destination_url` | `text` | Required, validated as an absolute HTTPS URL when created or changed. |
| `traffic_source_id` | `uuid` | Nullable foreign key to `traffic_sources(id)`, `ON DELETE RESTRICT`. |
| `default_currency` | `char(3)` | Required uppercase ISO 4217 code. |
| `allowed_tracking_parameters` | `jsonb` | Required, defaults to `[]`; explicit allowlist only. |
| `created_at`, `updated_at`, `archived_at` | `timestamptz` | First two required; `archived_at` nullable. |

Do not cascade-delete campaigns, traffic sources, or clicks. Historical attribution must remain intact.

### `clicks`

An immutable record created only after a valid active campaign is resolved.

| Column | Type | Rules |
| --- | --- | --- |
| `id` | `uuid` | Internal primary key. |
| `click_id` | `text` | Required opaque public identifier, unique. Generate it with cryptographic randomness, never from an ID or timestamp. |
| `campaign_id` | `uuid` | Required foreign key to `campaigns(id)`, `ON DELETE RESTRICT`. |
| `traffic_source_id` | `uuid` | Nullable foreign key to `traffic_sources(id)`, `ON DELETE RESTRICT`; snapshot the source selected for the click. |
| `clicked_at` | `timestamptz` | Required, default `now()`. |
| `ip_address` | `inet` | Nullable. Retention/anonymization policy is required before real traffic. |
| `user_agent`, `referrer` | `text` | Nullable, bounded in application validation. |
| `destination_url` | `text` | Required, the resolved destination actually used for the redirect. |
| `tracking_tokens` | `jsonb` | Required, defaults to `{}`; only campaign-allowlisted platform tokens. |
| `correlation_id` | `uuid` | Required request identifier; not a public click identifier. |

The first migration should place conservative application-level size limits on `user_agent`, `referrer`, `destination_url`, and serialized token data. PostgreSQL should also add `CHECK (jsonb_typeof(tracking_tokens) = 'object')`.

### `conversions`

An accepted money-site event associated with exactly one stored click.

| Column | Type | Rules |
| --- | --- | --- |
| `id` | `uuid` | Primary key. |
| `click_record_id` | `uuid` | Required foreign key to `clicks(id)`, `ON DELETE RESTRICT`. This explicit name avoids confusing an internal FK with the public `click_id`. |
| `source` | `text` | Required stable money-site identifier. For the one-site MVP, use the fixed value `primary_money_site`. |
| `event_id` | `text` | Required stable idempotency key supplied by the money site. |
| `event_type` | `text` | Required, validated against the configured event vocabulary in application code. |
| `occurred_at`, `received_at` | `timestamptz` | Required; `received_at` defaults to `now()`. |
| `value_minor` | `bigint` | Required, with `CHECK (value_minor >= 0)` in MVP. |
| `currency` | `char(3)` | Required uppercase ISO 4217 code. |
| `transaction_reference` | `text` | Nullable reconciliation reference, not a substitute for `event_id`. |
| `payload_hash` | `char(64)` | Required SHA-256 hex digest of a canonical, sanitized payload. Never persist arbitrary raw request JSON. |
| `validation_state` | `text` | Required, defaults to `accepted`; the initial conversion endpoint writes only accepted rows. |
| `correlation_id` | `uuid` | Required inbound-request identifier. |

Idempotency constraint: `UNIQUE (source, event_id)`. This is the authoritative replay guard. Add a nullable unique index on `(source, transaction_reference)` only if the money site guarantees that reference is globally unique for the event type; otherwise do not add it.

### `outbound_postbacks`

The transactional outbox record and current delivery ledger for one conversion/source/destination combination. It is inserted in the same transaction as a new conversion, never by a later best-effort action.

| Column | Type | Rules |
| --- | --- | --- |
| `id` | `uuid` | Primary key. |
| `conversion_id` | `uuid` | Required foreign key to `conversions(id)`, `ON DELETE RESTRICT`. |
| `traffic_source_id` | `uuid` | Required foreign key to `traffic_sources(id)`, `ON DELETE RESTRICT`. |
| `destination` | `text` | Required stable provider destination key, not a full secret-bearing URL. |
| `status` | `outbound_postback_status` | Required enum: `pending`, `processing`, `delivered`, `retryable_failed`, `permanently_failed`, `suppressed`; defaults to `pending`. |
| `attempt_count` | `integer` | Required, defaults to `0`, with `CHECK (attempt_count >= 0)`. |
| `next_attempt_at` | `timestamptz` | Required, defaults to `now()`. |
| `locked_at`, `locked_by` | `timestamptz`, `text` | Nullable worker lease fields. |
| `request_fingerprint` | `char(64)` | Nullable SHA-256 of sanitized canonical delivery inputs. |
| `last_response_status` | `integer` | Nullable, with `CHECK (last_response_status BETWEEN 100 AND 599)`. |
| `last_response_summary`, `last_error` | `text` | Nullable, sanitized and bounded. |
| `delivered_at` | `timestamptz` | Nullable. |
| `correlation_id` | `uuid` | Required identifier inherited from the conversion flow or retry action. |
| `created_at`, `updated_at` | `timestamptz` | Required, default `now()`. |

Uniqueness constraint: `UNIQUE (conversion_id, traffic_source_id, destination)`. A separate immutable attempt-history table is deferred until Phase 2, when the chosen provider and operator audit requirements are concrete. The outbox row retains the current classified delivery state and last sanitized result for the MVP.

## Required PostgreSQL types, constraints, and indexes

```text
campaign_status: active | paused | archived
outbound_postback_status: pending | processing | delivered |
  retryable_failed | permanently_failed | suppressed
```

Required unique constraints:

- `campaigns.slug` through `UNIQUE INDEX ... ON lower(slug)`.
- `traffic_sources.name` through `UNIQUE INDEX ... ON lower(name)`.
- `clicks.click_id`.
- `conversions (source, event_id)`.
- `outbound_postbacks (conversion_id, traffic_source_id, destination)`.

Required foreign keys use `ON DELETE RESTRICT`. This preserves click-to-conversion and conversion-to-postback history.

Required operational indexes:

- `clicks (campaign_id, clicked_at DESC)` for campaign drill-down and recent clicks.
- `clicks (traffic_source_id, clicked_at DESC)` where `traffic_source_id IS NOT NULL`.
- `conversions (click_record_id)` for attribution lookup.
- `conversions (received_at DESC)` and `(occurred_at DESC)` for reconciliation/reporting.
- `outbound_postbacks (status, next_attempt_at)` partial index where status is `pending` or `retryable_failed`, for worker claims.
- `outbound_postbacks (conversion_id)` for conversion reconciliation.

Do not create JSONB indexes until an actual provider lookup requires one. Token data is written for outbound mapping, not for arbitrary filtering.

## Transaction and locking contract

For a new conversion request, execute one database transaction:

1. Find the click by `click_id`.
2. Insert `conversions` with `(source, event_id)` idempotency protection.
3. Insert every applicable `outbound_postbacks` row.
4. Commit before responding `accepted`.

On a duplicate-key conflict for `(source, event_id)`, fetch and return the existing conversion as `duplicate`. Do not create another postback row.

Workers should claim due outbox rows with `FOR UPDATE SKIP LOCKED`, set a short lease, and update the existing record with a classified outcome. The detailed worker implementation belongs to Phase 2.

## Migration verification

The database task is complete only when the implementation verifies all of the following against a clean, disposable PostgreSQL database:

1. Apply the initial migration from an empty database.
2. Confirm all tables, enum types, foreign keys, unique constraints, check constraints, and indexes exist.
3. Insert a campaign and click, then demonstrate duplicate `click_id` rejection.
4. Insert an attributed conversion and outbox row in one transaction, then demonstrate duplicate `(source, event_id)` rejection without another outbox row.
5. Demonstrate foreign-key rejection for an unknown click, conversion, or traffic source.
6. Demonstrate that invalid outbox status, negative `attempt_count`, impossible HTTP response status, and non-object `tracking_tokens` are rejected where constrained.
7. Run the migration command a second time and confirm it is a no-op.

## Unresolved choices

- **Personal-data retention:** Choose whether `ip_address`, `user_agent`, and `referrer` are retained, truncated/anonymized, and for how long before processing real traffic. The schema keeps these nullable to support a privacy-minimized rollout.
- **Money-site identity:** The one-site MVP uses `primary_money_site` as `conversions.source`. If multiple money sites are required later, introduce a dedicated `money_sites` table and per-site authentication, rather than overloading free-form text.
- **Refunds and negative adjustments:** The initial `value_minor >= 0` constraint deliberately excludes them. Add explicit event rules and migrations only if the operator needs them.
- **Dashboard business timezone:** Store facts in UTC now. Select a business timezone before materialized daily metrics or day-based cost imports are introduced.
